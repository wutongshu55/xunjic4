## 一、项目简介

本项目是一套基于 STM32F103 标准库的**电磁循迹智能车固件**，面向校赛场景。车辆通过 4 路电磁电感采集地面 100Hz 交流导线产生的电磁场，经 ADC+DMA 高速采集、排序去极值滤波、归一化差比和求误差，由 PD 控制器输出差速驱动双电机转向。

除基础循迹外，本版本还包含：

- **赛道元素识别**：十字路口直行计数、起点线计圈、右侧六角菱形环（相对判据 + 闭环出环）
- **编码器测速**：TIM2/TIM4 正交解码，实时显示左右轮转速与线速度
- **OLED 菜单系统**：8 页参数配置（车速、六角菱形环、发车、标定、距离测试、Kp、Kd、急弯）
- **蜂鸣器事件提示**：过路口、过环、过圈、发车均有声音反馈

├──────────────────────────────────────────────────────┤

### 3.2 控制链路

```
地面导线（100Hz 交变电磁场）
    ↓
4 路电感（PA4~PA7）
    ↓
ADC1 规则组扫描（4 通道）+ DMA1_CH1 自动搬运
    ↓
ADC_TempDat[4] → ADC_Dat[20][4] 环形缓冲
    ↓
每 20 次采样 → ADC_Filter()（插入排序 + 去极值均值）→ ADC_Value[4]
    ↓
Get_Error()：归一化 → 差比和差 → Error（-100~+100）
    ↓
PID_Calculate()：PD → Speed_Delta
    ↓
Track_Judge()：赛道元素状态机（可覆盖 Speed_Delta）
    ├─ Cross_Judge()   十字路口
    ├─ Diamond_Judge() 菱形环
    ├─ HexDia_Judge()  六角菱形环
    └─ Lap_Judge()     圈数
    ↓
CarMotor_Control()：目标 L/R = Basic ± Δ(mm/s)      ← 外环输出的是"速度"
    ↓
速度 PI（每 20ms）：duty = FF×目标 + Kp×误差 + 积分   ← 内环输出的是"占空比"
    ↓
Motor_Out()：GPIO 方向 + PWM 占空比 → 电机
    ↑
编码器（TIM2/TIM4 正交解码）→ 20ms 窗口测速 → 实际 mm/s
```

**串级结构说明**：外环（循迹 PD，200Hz）管"往哪走"，内环（速度 PI，50Hz）管"走多快"。
内环把电池电压下降、左右电机差异、轻微打滑这些扰动在内部吃掉，外环感觉不到。

### 3.3 5ms 中断流程（TIM1_UP_IRQHandler）

```c
/* 1. ADC 采集：5ms 内采 20 次，触发一次滤波 */
for (i = 0; i < 20; i++) ADC_GetValue();
ADC_Calibrate();          // 标定模式时更新 MAX/MIN
Get_Error();              // 归一化 + 差比和误差

/* 2. 编码器：每 5ms 累加计数，每 20ms 算一次速度 */
Encoder_Update(0.005f);

/* 3. 蜂鸣器计时递减 */
Beep_Tick();

/* 4. 运行控制 */
if (Menu_Running == 1) {
    Speed_Basic = Speed_Level_MMS[Menu_SpeedLevel];   // 三档目标速度 mm/s
    PID_LostLine_Check();     // 丢线
    PID_Sharp_Check();        // 急弯
    PID_Calculate();          // 循迹 PD -> Speed_Delta
    Track_Judge();            // 元素 + 赛道状态机
    Speed_Delta = PID_Apply(Speed_Delta);              // 合成偏置/限幅
    Speed_Basic = PID_Speed_Schedule(Speed_Basic);     // 弯道降速
    CarMotor_Control();       // 目标速度 -> 速度 PI(每20ms) -> PWM
} else if (Menu_Running == 2) {
    Motor_Out(0, 0);  Speed_Loop_Reset();  Speed_Basic = 0;   // 完成停车
} else {
    Motor_Out(0, 0);  Speed_Loop_Reset();                     // 待发车
}
```

主循环 `while(1)` 仅负责取按键事件与 OLED 刷新，**不参与控制运算**，保证控制周期稳定。
> 按键扫描在中断里（`Key_Scan_5ms()`），主循环只从队列取事件——因为主循环一轮要
> 刷 32 个数字（软件 I2C）+ `Delay_ms(50)`，共 100~200ms，在主循环里扫必然漏掉点按。

## 五、核心算法与数学原理

### 5.1 ADC + DMA 采集

- ADC1 规则组扫描 4 通道（CH4~CH7），扫描模式 + 软件触发
- DMA1_Channel1 外设到内存，半字宽度，传输 4 个样本到 `ADC_TempDat[4]`
- 每次采集前重配 DMA 计数器（`DMA_SetCurrDataCounter`），防止上次转换残留导致数据错位
- `while (DMA_GetFlagStatus(DMA1_FLAG_TC1) == RESET)` 等待传输完成

### 5.2 排序去极值均值滤波

对每个电感的 20 个样本做**插入排序**，去掉最小值与最大值，剩余 18 个求算术平均：

$$
\text{ADC\_Value}[n] = \frac{1}{18}\sum_{i=1}^{18} \text{ADC\_Dat}[i][n]
$$

其中 `ADC_Dat[0]` 为最小值、`ADC_Dat[19]` 为最大值，均被剔除。

**为什么用排序去极值而不是简单平均？**

电磁感应在导线接头、金属异物附近会产生**脉冲尖峰**，简单平均会被单个尖峰拉偏。排序去极值对脉冲干扰的抑制效果接近中值滤波，同时保留了均值的平滑性，且 20 个样本的插入排序在 M3 上耗时极短（约几十微秒），满足 5ms 实时性要求。

### 5.3 归一化

将原始 ADC 值（0~4095）线性映射到 0~100：

$$
\text{ADC\_L} = \frac{\text{ADC\_Value}[0] - \text{ADC\_MIN}[0]}{\text{ADC\_MAX}[0] - \text{ADC\_MIN}[0]} \times 100
$$

ML/MR/R 同理。带除零保护（分母 ≤ 0 时取 1）与限幅（0~100）。

**作用**：消除四路电感因线径、匝数、安装高度、放大器增益不同造成的个体差异，使误差计算与具体传感器解耦。

### 5.4 传感器布局与差比和误差（核心）

本车采用**复合（十字）型电感布局**，横置与竖置分工不同：

| 位置 | 引脚 | 朝向 | 职责 | 权重 | 直道典型读数 |
|---|---|---|---|---|---|
| 左 | PA7 | **横置** | 循迹主力，判断左右偏差 | **80%** | 1500~2500 |
| 中左 | PA6 | **竖置** | 特殊元素探测（十字/环岛） | 20% | ≈0（接近 0 属正常） |
| 中右 | PA5 | **竖置** | 特殊元素探测（十字/环岛） | 20% | ≈0 |
| 右 | PA4 | **横置** | 循迹主力，判断左右偏差 | **80%** | 1500~2500 |

> **横置与竖置的绝对值不能互比**：横置线圈轴线垂直于导线，导线从侧方经过时耦合最强，
> 直道上就有很大读数；竖置线圈轴线竖直，直道上磁场几乎全是水平方向，耦合接近 0。
> 所以归一化**逐通道各用自己的峰值**（`ADC_MAX[i]`），横竖不要求一致；
> 误差与判据都是**各类型先各自归一化、再按权重合成**。

误差公式（80/20 加权）：

$$
e_h = \frac{L - R}{L + R}, \qquad e_v = \frac{ML - MR}{ML + MR}
$$
$$
\text{Error} = \frac{A \cdot W_{out} \cdot e_h + B \cdot W_{in} \cdot e_v}{A \cdot W_{out} + B \cdot W_{in}} \times 100
\quad (-100 \sim +100)
$$

其中 $W_{out}=4$（横置）、$W_{in}=1$（竖置）→ 4:1 = **80% : 20%**。

- **各自归一化再合成**：竖置在直道上接近 0，若直接塞进同一个分子/分母，只会把分母冲淡、把误差压小；
  到十字/环岛竖置猛升，又会把误差绑架而满舵。先各自归一化后，「横置全丢、只剩竖置」时 $e_h=0$ 而不是被放大
- **有效门限**：$L+R < 4$ 或 $ML+MR < 30$ 时对应项直接旁路，避免几 LSB 噪声被放大成满量程误差
- **误差量纲变化**：纯横置偏摆时竖置无贡献，|Error| 上限为 80；
  同样工况下绝对值约为旧版四路全横置的 **1.34 倍**，所以 `PID.c` 里所有以 Error 为量纲的门限与增益都按 1/1.34 缩小
- **全程浮点** + **一阶低通**（α=0.5）：抑制量化抖动，避免其进入 PD 的 D 项

> 完整推导、标定方法与实测见 [电磁循迹优化说明.md](电磁循迹优化说明.md)。

### 5.5 PD 控制

$$
\text{Speed\_Delta} = k_p^{eff} \cdot \text{Error} + k_d^{eff} \cdot \text{D\_Filt}
$$

- 默认 `kp = 11.0`、`kd = 3.7`（已按新量纲缩放，菜单可在线调）
- **D 项先低通**（α=0.3）再进控制，消除 ADC 抖动
- **按速度调参**：高速时 Kp 降 15%、Kd 升 35%，直线不蛇形
- **弯道降速调度**：|Error| 越大基础速度越低（15~45 之间降到 70%，45 以上降到 50%）
- **丢线保护**：总场强过低时按最后偏差方向低速找线（45% 速度）
- **急弯保持**：|Error| 饱和（>41）连续 3 周期即锁定转向方向（锯齿线/直角弯）

差速输出：

$$
L_{\text{speed}} = \text{Speed\_Basic} + \Delta\text{,} \quad
R_{\text{speed}} = \text{Speed\_Basic} - \Delta\text{,}
$$

Error > 0（右偏）时左轮加速、右轮减速，车辆向右修正。

### 5.6 编码器测速

TIM2/TIM4 配置为 **TI12 正交解码模式**（4 倍频），每个控制周期读取并清零计数器：

$$
N_{\text{rev}} = \frac{\Delta \text{Count}}{\text{COUNTS\_PER\_REV}}, \quad
\text{COUNTS\_PER\_REV} = \text{PPR} \times 4 \times \text{GEAR\_RATIO} = 11 \times 4 \times 20 = 880
$$

转速（RPM）：

$$
\text{RPM} = \frac{\Delta \text{Count}}{880} \times \frac{60}{\Delta t}
$$

线速度（mm/s）：

$$
v = \frac{\Delta \text{Count}}{880} \times \pi D \times \frac{1}{\Delta t}
= \frac{\Delta \text{Count}}{880} \times 150.80 \times \frac{1}{0.005}
$$

其中 $D = 48\text{mm}$ 为轮子外径。

> **采样周期不是 5ms，而是 20ms**（`Encoder.c` 的 `SPEED_WIN_MS`）。
> 计数每 5ms 累加一次，但每 20ms 才算一次速度：
>
> | 测速窗口 | 1 个计数 = | 300mm/s 时的计数 | 量化误差 |
> |---|---|---|---|
> | 5ms | 34.3 mm/s | 9 | >10% |
> | **20ms** | **8.6 mm/s** | **35** | **约 3%** |
>
> 5ms 窗口下速度环会把量化跳变当成真实速度去追，输出直接抖。这是速度闭环能用 50Hz 的前提。
> 算完后过一阶低通（系数 `SPEED_LPF = 0.5`），抑制单个窗口的跳变。

### 5.7 赛道元素状态机

#### 状态机总览（8 个状态）

元素识别不是"一个个 if 判断"，而是一个**带优先级和滞回的状态机**（`Ring_Judge.c: Track_Classify()`）。
每个状态决定两件事：**速度系数**和**D 增益倍数**（通过 `Track_Kd_Gain` 作用到 PD 的微分项）。

| 值 | 状态 | 识别依据 | 速度系数 | D 倍数 |
|:--:|---|---|:--:|:--:|
| 0 | 直道 | `|E| < 22` | 1.00 | 1.0 |
| 1 | 普通弯 | `|E| > 22` | 1.00（误差调度降速） | 1.0 |
| 2 | 直角弯 | `|E| > 41` 持续 15ms | 1.00（急弯逻辑降到 0.55） | 1.0 |
| 3 | 双直道 / S 弯 | 900ms 内方向反转 2 次 | 0.65 | 1.6 |
| 4 | 十字路口 | 竖置主导 + 横置对称 | 1.00 | 1.0 |
| 5 | 六角菱形环 | 横置强右偏 + 竖置抬头 | 环状态机给 | 1.0 |
| 6 | 半圆弧 | `|E|` 在 40~80 持续 400ms | 0.90 | 1.1 |
| 7 | 锯齿 | 250ms 内方向反转 3 次 | 0.55 | 1.8 |

**判据优先级**（顺序错了就永远进不去某个状态）：

```
十字 > 六角环 > 锯齿 > S弯 > 半圆弧 > 直角弯 > 普通弯 > 直道
```

两个关键取舍：

1. **方向反转排在圆弧前面**：锯齿和 S 弯同样会持续大误差，若让圆弧优先，锯齿永远进不去。
2. **圆弧排在直角弯前面，但有上限 `ARC_MAX_ERR = 80`**：两者误差都大，
   区别在于圆弧的误差**稳在 45~80**（几何上偏差有限），直角弯往往**直接顶到 90~100**。

**三个滞回机制**：新状态连续确认 2 周期（10ms）才切；S 弯/锯齿进入后至少保持 300ms；
`|E| < 10` 持续 200ms 才清空反转计数（防止拖尾到后面的直道）。

> 状态机是**辅助**不是**替代**：`PID_Apply()` 里的急弯"锁方向 + 固定偏置"仍然保留。
> 调参拿不准时先把 `Sharp` 页关掉，只看纯 PD，能分清"识别错了"还是"PD 本身不行"。

#### 十字路口（靠中间竖置电感）

复合布局下，十字路口的判据**完全交给竖置电感**——这正是"竖置 = 特殊元素探测器"的本职：

| 条件 | 说明 |
|---|---|
| 竖置场强 `V ≥ 40` | 竖置归一化后达到自身峰值的 40%（其峰值就是在十字处标定的） |
| 竖置相对自身巡航基线抬升 ≥ 1.8 倍 | 基线偏高时的兜底判据，防止标定漂移导致误判 |
| **横置左右偏差 ≤ 45%** | 排除 90° 直角弯（见下） |

动作：**直行通过不转弯**，计数 +1，蜂鸣 30ms。连续成立 ≥ 4 周期确认，中途允许断 5 周期。

> **为什么还要"横置左右对称"这一条**：90° 直角弯处，前方那根横着的导线同样会从中间
> 竖置电感下面扫过，竖置一样会抬头——只凭竖置会把直角弯误判成十字，车被强制直行冲出去。
> 区分点：十字是**两根导线同时存在**，左右横置都被激励 → 基本对称；
> 直角弯是车正在转，导线偏向一侧 → 横置左右明显不对称。
> 注意这里比的是**横置自己内部**的 L 与 R，仍然没有和竖置互比。
>
> **为什么不用"四路齐平"**：竖置在直道上本来就接近 0，永远不可能和横置"齐平"，
> 用四路的 min/max 会**永远检不出十字**。

#### 起点线与十字路口的区分

按"特征真正成立的周期数"区分（`pat` 计数，不含间断容忍）：

| 持续时间 | 判定 | 动作 |
|---|---|---|
| 4 ~ 45 周期(20~225ms) | 普通十字路口 | 直行通过，`Menu_CrossCount++`，蜂鸣 30ms |
| > 45 周期 | 宽的起点线 | `Menu_DoneLaps++`，蜂鸣 100ms，达到目标圈数则停车 |

#### 菱形环（暂不启用，保留接口）

`Diamond_Judge()` 目前是空实现，状态机结构保留备用。

#### 六角菱形环（赛道右侧进入，顺时针绕行）

| 阶段 | 动作 | 转移条件 |
|------|------|---------|
| 0 | 检测入口：**横置强右偏**（R 为较强侧且右偏 ≥45%）且 **竖置抬头**（≥20），连续 10 周期 | 满足 → 1 |
| 1 | 强制右转 `Track_Steer_Bias = -900`，速度 60% | 40 周期(200ms) → 2 |
| 2 | 环内轻偏置 `-300`，速度 72%；**丢线时改用找线偏置 `-700`、速度降到 58%** | **导线从左侧重新出现（绕完一圈）** 或 220 周期超时 → 3 |
| 3 | 出环偏置 `-500`，速度 70% | 误差回中或 60 周期超时 → 0 |

> **入口为什么要求"竖置也抬头"**：普通右弯只有横置强右偏、竖置始终接近 0；
> 六角菱形环的回线会从侧面扫过中间，竖置会被激励起来。两条同时成立才认，普通右弯不会误触发。
>
> **为什么环内要单独处理丢线**：多边形（六角/菱形）有尖角，电感可能长时间压不到导线。
> 这时"继续按原方向转去找线"比"丢线保护模块接管"更合适，所以六角菱形环状态下
> 丢线保护与急弯保持都会让位给环状态机（见 `PID_Apply()`）。
>
> **为什么出环靠左侧重现**：绕完一圈后导线会从车的左侧重新出现，
> 这比"等固定时间"更稳，车速变化时不会过冲或卡在环里。

#### 锯齿线 / 直角弯（急弯保持）

| 条件 | 动作 |
|---|---|
| `|Error| > 41` 连续 3 周期 | 进入急弯模式：锁定转向方向 + 偏置 ±350 + 速度降到 55% |
| `|Error| < 19` 连续 3 周期，或超过 60 周期 | 退出急弯模式 |

菜单 `Sharp` 页可开关。原理：锯齿线难的不是转不过去，而是 PD 在两路传感器之间来回抽动，
锁定方向后车会"一拐到底"，回中再放开。

### 6.1 按键

| 按键 | 引脚 | 菜单模式 | 运行模式 |
|:----:|:----:|:--------|:--------|
| KEY1 | PA9 | 上一页 | 应急暂停（保留圈数）回调试页 |
| KEY2 | PA10 | 下一页 | 同上 |
| KEY3 | PA11 | 数值减 | 同上 |
| KEY4 | PA12 | 数值加 / 确认 | **停车** → 回发车页（IDLE） |
| **KEY4 长按(0.8s)** | PA12 | **进入调试页** | 暂停并回调试页 |

> **停车键**：发车后按 KEY4 即停车（**按下即停，约 25ms 消抖，不等松开**），并跳到发车页显示 `IDLE`，再按一次 KEY4 就能重新发车。
> 停车与发车走同一套逻辑（`Menu_KeyHandler` 的发车页分支），不会出现两处对
> `Menu_Running` 判断不一致的问题。若上一次已经跑满圈数，重新发车会**自动清零圈数和十字计数**，
> 否则会带着旧圈数、跑一圈就停。
| **KEY4 长按(0.8s)** | PA12 | **进入调试页** | **暂停并回调试页** |

> **KEY4 短按与长按分开了**：短按就是本页的"数值加/确认"，长按约 **0.8 秒** 才切换
> 调试页 ↔ 菜单。这样在车速页连按 KEY4 加档位时，不会一按就被弹进调试页。
> 按住时长由 `Key.h` 的 `KEY_LONG_MS` 控制（默认 800，嫌容易误进就加大）。
>
> **实现要点**：
> 1. 短按事件改为**松开时**才产生，所以长按不会同时触发一次短按功能；
> 2. **按键扫描放在 TIM1 的 5ms 中断里**（`Key_Scan_5ms()`），事件进环形队列由主循环取。
>    原来在主循环里扫是行不通的：运行页每轮要刷 32 个数字（软件 I2C）+ `Delay_ms(50)`，
>    主循环一轮 100~200ms，短于一整轮的点按会**整个被漏掉**——这就是"跑起来按 KEY4 没反应"的原因；
> 3. **运行中的停车在中断里做**：KEY4 按下（消抖 20ms）就把 `Menu_Running` 置 0，
>    本次按下随后被"消费"掉、不再产生事件，避免主循环又把它当成"发车"处理。

>
> | 模式 | 标题 | 显示内容 | 用途 |
> |:--:|---|---|---|
> | 0 | `== Dist N ==` | 四路归一化值 + 综合/横置/竖置场强 | 检查归一化是否合理 |
> | 1 | `= Dist Raw =` | 横置(L,R) / 竖置(ML,MR) 原始值 + `SAT` 位图 | 实时读数 |

### 6.3 三档车速

现在给的是**目标线速度 mm/s**，由速度闭环执行（不再是 PWM 占空比）：

```c
const int16_t Speed_Level_MMS[3] = {300, 480, 700};  // 目标速度 mm/s
```

| 档位 | 目标速度 | 适用场景 |
|:----:|:---:|:--------|
| 慢 | 300 mm/s | 调试、过密弯、过环岛 |
| 中 | 480 mm/s | 默认，兼顾稳定与速度 |
| 快 | 700 mm/s | 直线冲刺 |

> **换了档位不用重调 PD 的比例关系**：差速量按基准归一（`Δ_mms = Speed_Delta × Speed_Basic/5000`），
> 所以三档的"转向强度/速度"比例一致，只需按需微调 kp/kd 的绝对值。

> 实际速度还会被**弯道降速调度**二次缩放：|Error| 越大，实际基础速度越低。

| 字段 | 含义 | 正常值 / 怎么看 |

| `L` `R` | 左/右**横置**归一化 | 直道 40~70；差值 <5% 说明配平了 |
| `ML` `MR` | 左/右**竖置**归一化 | 直道 5~20（接近 0 正常）；十字 85~100 |
| `E` | 循迹误差，**正 = 车偏左** | 直道 ±5 内；过弯 40~90 |
| `S` | 综合场强（横竖合计） | 直道约 40~60，越靠近导线越高 |

| `L1/2` | 已完成圈数/目标圈数 | 过起点线 +1 |
| `S2` | **赛道状态**（见下表） | 见下 |
| `X03` | 十字计数 | 每过一个十字 +1 |
| `D4800` | 左轮占空比 | 300mm/s 直道约 5500~6500 |

| 2 | 直角弯 | 锁方向 + 350 偏置 + 55% 速度 |

| 5 | 六角菱形环 | 交给环状态机 |
| 6 | 半圆弧 | 90% 速度，D 增益 ×1.1 |
| 7 | 锯齿 | 55% 速度，D 增益 ×1.8 |

## 七、参数标定指南

### 7.1 电位器调节（硬件，先做）

复合布局的调节原则是 **横向调对称、竖向防饱和、两者不互比**。

| 步骤 | 操作 | 判定标准 |
|:--:|---|---|
| 0 | 所有电位器逆时针到底，再顺时针约 14 圈到中间位 | 增益适中起点 |
| 0 | 万用表确认运放 **第11脚(V-)=0V**、**第4脚(V+)=3.3V** | 供电错则一切无效 |
| 1 | 车放直道导线正上方、导线对车体中心 | — |
| 2 | **调两侧横置**：使 L 与 R 读数一致（误差 ≤5%） | 直道居中时 **1500~2500** |
| 3 | **调中间竖置**：使 ML 与 MR 一致 | 直道上接近 0 属正常；**不要求与横置一致** |
| 4 | 车推到**十字/环岛交叉点**，用 `Dist` 峰值模式看峰值 | **3200~3600（上限 3700，绝不能到 4095）** |
| 5 | 低速跑一圈 | 赛道边缘横置不归零；直道左右差不频繁跳动；过弯外侧明显高于内侧 |

> 第 4 步超 3700 → 逆时针降该通道增益；远低于 3200 → 顺时针加一点提高信噪比。

### 7.2 ADC_MAX / ADC_MIN（软件标定）

`All_Init.c` 默认 `3600 / 200`（与"峰值上限 3700"配套）。**横置与竖置的 MAX 含义不同**：

| 通道 | MAX 取自 | 说明 |
|---|---|---|
| 横置 L/R | 正常巡航姿态下**直道居中**的读数 | 调好后约 1500~2500 |
| 竖置 ML/MR | **十字/环岛交叉点**的峰值 | 约 3200~3600 |

两者绝对值**不要求一致**——每路 100 代表各自的峰值。这就是"横竖不互比"在软件上的体现。

1. 车放无电磁场处，读 4 路值作为 `ADC_MIN[i]`
2. 按上表分别取 `ADC_MAX[i]`
3. 写入 `All_Init()`；或在 `Calib` 页开**自动标定**，运行时 MAX 跟随实际峰值、缓慢回落

> 自动标定的意义：车高/电池电压/赛道变化后不需要重烧固件。
> 因为元素判据是"占自身峰值的百分比"，**标定跟随是它在不同高度都能工作的前提**。
> 若关掉自动标定且车高变化较大，十字/环会漏检——这不是判据失效，而是量程失配。

### 7.3 PD 参数 kp / kd

`PID.c` 中默认 `kp = 11.0, kd = 3.7`（已按新误差量纲缩放，约为旧版 15/5 的 1/1.34），
菜单 `Kp`/`Kd` 页可在线调（不用重烧）。

| 现象 | 调整 |
|------|------|
| 弯道振荡、直道蛇形 | 减小 kp 或增大 kd |
| 弯道冲出 | 增大 kp，或检查弯道降速调度是否生效 |
| 高频抖动 | 减小 kd（D 项低通系数 D_LPF 也可调） |
| 响应慢、超调大 | 增大 kd |

### 7.4 布局权重 W_OUT / W_IN

`ADC.c` 中 `W_OUT = 4.0`（横置）、`W_IN = 1.0`（竖置）→ **80% : 20%**。

| 权重 | 作用 |
|------|------|
| `W_OUT` | 横置（循迹主力）权重 |
| `W_IN` | 竖置（元素探测）权重，直道上通常无信号 |
| A / B | 对上述两类权重的整体微调，默认 1.0 一般不用改 |
| C | 旧版分母修正项，**已不参与运算**，保留仅便于回退对比 |

> 想让循迹更"听横置的话"就把 `W_IN` 降到 0.5（≈89%/11%）。
> **改权重后必须同步复查 `PID.c` 里所有以 Error 为量纲的常数**（原因见 5.4 末条）。
| C | 分母中 \|ML-MR\| 修正强度，**建议保持 0**，仅用于对比回退 |

外侧/内侧的间距权重由 `W_OUT=3.0`、`W_IN=1.0` 固定（不要改 A/B 除非电感间距不是等距）。

### 7.4 编码器线数 ENCODER_PPR

`Encoder.c` 中默认 11。若实测转速显示值与实际不符，修改此值：

$$
\text{显示值} \times \frac{\text{实际PPR}}{11} = \text{真实值}
$$

| 参数 | 默认 | 说明 |

| `CROSS_V_MIN` | 40 | **十字：竖置场强须达自身峰值的 40%**（竖置的峰值就在十字处标定） |
| `CROSS_V_BASE_MIN` / `CROSS_V_RISE` | 8 / 1.8 | 竖置基线偏高时，还须达到自身基线的 1.8 倍 |
| `CROSS_BAL` | 45 | **横置左右偏差须 ≤45%**，用于排除 90° 直角弯（百分比） |
| `CROSS_CONFIRM` | 4 | 十字路口确认周期数（×5ms = 20ms） |

### 7.6 速度环标定（新增）

速度环里有前馈系数 `SPEED_FF_GAIN = 12.5`（`Motor.c`），含义是"1mm/s 需要多少占空比"，
理论值 = `10000 / 满速`。标定 5 分钟：

1. 菜单第 11 页 `Loop` 改成 **0（开环，仅前馈）**；
2. 第 1 页车速选中档（480 mm/s），把车架空或按住；
3. 看运行页：`T480`（目标）、`A430`（实测）、`D5544`（占空比）；
4. 算 `FF = D / A = 5544 / 430 ≈ 12.9`，改 `Motor.c` 的 `SPEED_FF_GAIN`。

前馈不准只会让起步/换档稍慢，稳态由积分保证，所以默认 12.5 通常够用。

| 参数 | 默认 | 菜单页 | 调大 | 调小 |
|---|:--:|:--:|---|---|
| `Speed_KpS` | 12.0 | 9 | 响应快、易抖 | 平滑但迟钝 |
| `Speed_KiS` | 60.0 | 10 | 消差快、超调大 | 无超调、回正慢 |
| `SPEED_DUTY_DEAD` | 1200 | `Motor.c` | 低速更有力 | 低速细腻但可能起不来 |

判据：手推车能感到"有劲顶回来"但不发麻；跑起来是平稳的"呜——"，不是"嗡嗡"抖。
仿真 `sim/speed_sim.exe` 会自动打印 Kp/Ki 扫描表，可对照。

## 十、已知限制与改进方向

| 项 | 现状 | 改进建议 |
|----|------|---------|
| 速度闭环 | 编码器仅显示，未参与控制 | 用 `Speed_L_mms`/`Speed_R_mms` 做速度闭环，替代开环 PWM（**下一版最该做的**） |
| 环岛通过 | 转向开环偏置，出环时机已改为看传感器 | 引入陀螺仪做环内姿态闭环 |
| 远距离循迹 | 横置有效范围 0~15cm；元素判据依赖标定跟随车高 | 远距离场景改用摄像头/红外循迹 |
| 参数调试 | kp/kd 已在菜单可调，仍需重烧其它参数 | 串口（PA2/PA3 已预留）输出 `L,ML,MR,R,H,V,Error,Δ` 并支持在线写参 |
| ADC 标定 | 已支持菜单自动标定 + 峰值保持 | 自动标定与固定标定切换已实现，可再加"标定质量指示" |
| 制动 | 无主动刹车 | 出环/停车阶段加能耗制动 |
| OLED 刷新 | 软件 I2C 约 50ms/帧 | 改硬件 I2C 或 SPI OLED 提速 |
